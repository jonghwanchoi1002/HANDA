# 소개 페이지와 서식 편집

## 관리자 편집

**내 계정 → 콘텐츠 관리 → HANDA 소개**에서 HANDA란?, 운영 방식 및 참여 안내, 참여 신청하기를 수정합니다. 페이지 제목·본문 제목·본문·추가 안내와 참여 버튼 문구·URL을 관리할 수 있습니다. 소개 페이지 3개는 고정 주소를 사용하며 저장하면 바로 공개됩니다. 일반 멤버는 이 편집 화면과 저장 기능에 접근할 수 없습니다.

`011_editable_introduction_pages.sql`은 `page` 콘텐츠 종류와 고정 페이지 제약을 추가하고 세 페이지의 초기 내용을 넣습니다. 이 마이그레이션에는 처음 전달받은 소개 글이 초기 이력으로 남아 있습니다. 이미 적용했을 수 있으므로 마이그레이션 파일은 수정하지 않습니다. HANDA란?·운영 방식 페이지의 본문 아래 참여 버튼은 관리자가 지정한 링크를 새 탭으로 엽니다. 참여 신청하기 페이지의 **HANDA 참여 신청하기** 버튼은 모집 안내 팝업을 엽니다. 하단 **다음 모집 안내받기**와 팝업의 같은 이름 버튼은 `https://forms.gle/SXXxb8321efoPFta8`을 새 탭으로 엽니다. 이미 저장된 소개 페이지가 있으면 덮어쓰지 않습니다. 모집 안내 팝업은 현재 정기 모집 기간이 아님을 알리고 다음 모집 소식을 받을 수 있는 폼으로 연결합니다.

## 작성 도구

위키·멤버 소개·정기모임 후기·멤버 후기·홈 소개·소개 서브페이지의 제목과 본문에 공통 편집기를 제공합니다.

- 크기: 기본 / 12·14·16·18·20·24·28·32·40·48px
- 글자 색상 선택과 기본 색상 복원
- 굵게, 기울임, 밑줄, 서식 지우기
- 기본 실행 취소·다시 실행 및 서식 단축키

분류·날짜·URL·관심 분야 같은 구조화된 입력과 사진 설명은 일반 입력을 유지합니다. 기존 글은 서식이 없는 상태로 그대로 읽고 수정할 수 있습니다. 멤버 위키의 소유권·공개 승인과 사진 접근 규칙도 유지합니다.

## 저장과 표시

일반 문자열과 문자열 배열은 검색·제목·메타데이터에 계속 사용합니다. 필드별 `richText` JSON, 위키 섹션의 `titleRichText`/`bodyRichText`, 후기 블록의 `richText`에 서식만 추가합니다. 서버는 문서 구조·허용 글씨 크기·마크를 검사하고 색상은 6자리 HEX만 허용합니다. 일반 텍스트와 서식 내용이 일치해야 저장합니다.

문단·제목·목록·체크리스트·줄바꿈·텍스트와 허용된 서식만 저장합니다. HTML 문자열을 실행하거나 `dangerouslySetInnerHTML`로 표시하지 않습니다. 임의 노드·속성·스타일은 서버에서 거절하며 화면은 React 요소로 렌더링합니다. 기존 리비전 검사와 감사 기록을 사용하므로 동시 수정이 다른 관리자의 내용을 덮어쓰지 않습니다.

## 실제 콘텐츠의 기준

`CONTENT_SOURCE=database`에서는 소개 페이지를 DB에서만 읽습니다. DB 연결 실패나 누락된 페이지를 로컬 예시로 숨기지 않습니다. `src/data/pages.ts`는 명시적인 sample 모드와 신규 초기화에만 쓰는 짧은 준비 중 문구이며 실제 소개 본문이나 서식 문서를 담지 않습니다.

관리자는 콘텐츠 관리 폼에서 글을 작성·수정해 DB에 저장합니다. seed는 `ON CONFLICT DO NOTHING`을 사용하므로 파일의 문구를 바꾸거나 초기화를 다시 실행해도 기존 DB 글을 덮어쓰지 않습니다. 이번 정리는 기존 DB 본문을 지우지 않으며 추가 마이그레이션도 필요하지 않습니다.

색상 선택은 공통 편집기 전체에 적용되며 글씨 크기·굵기·기울임·밑줄과 함께 저장합니다. 기본 색상 복원은 다른 서식을 유지하며, 서식 지우기는 색상을 포함한 모든 텍스트 서식을 제거합니다. 기존 JSON의 선택 속성을 확장하므로 색상 기능 자체에는 추가 DB 마이그레이션이 필요하지 않습니다.

## 멤버 후기의 요약과 섹션 본문

`quote`는 **한 줄 후기**이며 목록 카드와 상세 페이지 제목에 사용합니다. 본문은 `sections`에 저장하며, 저장 시 최소 한 개의 섹션과 각 섹션의 비어 있지 않은 내용이 필수입니다. 번호와 제목은 선택입니다. 기본 섹션 하나에서 시작해 최대 30개까지 추가·순서 변경·삭제할 수 있습니다. 마지막 한 섹션은 삭제할 수 없습니다. 제목은 기본 테라코타 계열 색상으로 표시하며 섹션 사이에 경계선을 둡니다. ‘태그 형식으로 표시’를 선택하면 줄바꿈마다 개별 세이지색 태그로 표시합니다. 멤버 소개의 관심 분야와 같은 태그 디자인을 사용하며, Enter와 Shift+Enter 줄바꿈 모두 지원합니다. 빈 줄은 표시하지 않습니다. 글씨 크기·색상 등 기존 서식도 지원합니다.

마지막 세이지색 참여 안내 박스는 `closingTitle`, `closingBody`, `joinLabel`, `joinUrl`을 사용하며 모두 선택 입력으로 콘텐츠 관리에서 수정할 수 있습니다. 비워 둔 제목과 본문은 표시하지 않고, 버튼은 문구와 링크가 모두 있을 때만 표시합니다. 표시할 항목이 없으면 박스 전체를 숨깁니다. 명시적으로 비운 값은 저장 후에도 빈 상태로 유지됩니다. 마무리 안내 제목의 편집기 기본색도 테라코타 주황색입니다. 기본 신청 주소는 `https://forms.gle/SXXxb8321efoPFta8`이며 새 탭으로 열립니다. HTTP(S) 이외의 링크는 서버에서 거절합니다.

`012_testimonial_sections.sql`은 DB에 저장된 기존 단일 본문과 서식을 한 섹션으로 옮기고, 본문이 없는 예시 글에만 짧은 예시 본문을 추가합니다. 이미 섹션이 있는 글은 덮어쓰지 않습니다. 실제 글의 본문이 비어 있으면 임의로 내용을 만들지 않고, 다음 관리자 저장 시 필수 본문을 작성하도록 합니다. 예전 데이터도 읽을 수 있지만 새 저장은 본문 없는 글을 허용하지 않습니다. 로컬 예시 `src/data/testimonials.ts`에도 기본 섹션을 제공합니다. DB 모드에서 해당 파일을 바꾸는 것만으로 기존 글이 변경되지는 않습니다.

개발 환경에서는 아래 명령으로 기존 데이터를 전환한 뒤 확인합니다. 운영에는 배포 시 동일한 012 마이그레이션이 필요합니다.

```bash
npm run db:migrate
npm run dev
```

카드 하단 **후기 보기**는 `/testimonials/[slug]`로 이동합니다. 상세 조회도 목록과 동일하게 공개 상태와 공개 동의를 확인하며 임시 저장·미동의 글·존재하지 않는 글은 공개하지 않습니다.

홈 화면은 콘텐츠의 일반 텍스트만 사용하고 저장된 글씨 크기·색상·굵기·기울임·밑줄을 적용하지 않습니다(`ContentText formatted={false}`). 메인 문구, About, 멤버 미리보기, 마지막 멤버 후기 모두 홈 디자인의 서식을 따릅니다. 원본 서식은 DB에 유지되며 각 콘텐츠 페이지와 편집기에서는 그대로 사용합니다.

멤버 후기의 섹션 번호와 제목 기본색은 Terracotta Deep(`#A94A27`)이며 본문은 Ink(`#231F1C`)입니다. 편집기에서도 같은 기본색을 미리 보여주되 서식 데이터에 기본색을 강제로 저장하지 않습니다. ‘기본 색상’은 명시적인 색상만 지워서 제목은 주황색, 본문은 검은색으로 돌아갑니다. Sage(`#DDE1D6`)는 개별 태그와 참여 안내의 배경색입니다.

공통 편집기는 드래그로 선택한 텍스트 범위를 툴바에 포커스가 이동하기 전에 보관하고, 필요한 경우 명령 실행 시 복원합니다. 색상 선택창이나 글씨 크기 메뉴를 사용해도 선택한 부분에만 적용하며, 굵기·기울임·밑줄·기본 색상·서식 지우기도 같은 선택 범위를 사용합니다. 커서만 놓은 상태에서 여러 서식을 켜고 이어 쓰는 동작도 유지합니다.

## 멤버 웹사이트 이름

각 웹사이트에 이름과 주소를 선택 입력합니다. 이름이 있으면 이름에 링크를 걸고, 이름이 없으면 프로토콜을 제외한 주소 뒤에 ↗만 표시합니다. 주소가 없는 항목은 저장하지 않습니다. 기존 단일 웹사이트와 주소 목록은 이름이 빈 링크로 불러오며, 수정 후에도 이름과 주소 순서가 함께 유지됩니다. 웹사이트는 사진 첨부 수에 포함되지 않습니다. JSON 콘텐츠에 선택 필드를 사용하므로 별도 DB 마이그레이션은 필요하지 않습니다.

## 확장된 문서 도구 모음

문단 스타일(일반 텍스트·제목 1~3), 글꼴, 기존 크기 드롭다운, 글자 색상, 굵게·기울임·밑줄을 제공합니다. 왼쪽·가운데·오른쪽·양쪽 정렬, 줄 간격, 글머리표·번호 목록, 중첩 목록과 문단 들여쓰기·내어쓰기, 실행 취소·다시 실행, 서식 지우기도 지원합니다. 배경색·링크·댓글 기능은 포함하지 않으며 사진은 기존 첨부 기능으로 관리합니다.

기존 문단 JSON은 그대로 읽습니다. 신규 서식도 JSON에 저장하므로 DB 마이그레이션은 필요하지 않습니다. 공개 화면은 허용된 속성만 React 요소로 렌더링하며 임의 HTML을 실행하지 않습니다. 중첩 목록의 텍스트도 평문 검색·검증에 포함하고, 후기의 태그 표시 시에도 각 줄과 글자 서식이 유지됩니다. 폰트는 방문자 기기에 설치된 글꼴을 사용하므로 기기별로 대체 글꼴이 적용될 수 있습니다. 체크리스트 작성 기능은 제거했습니다. 이전에 저장된 체크리스트는 편집 시 일반 목록으로 읽어 내용을 유지합니다.

```bash
node --import tsx --test tests/rich-text.test.ts tests/expanded-rich-text.test.ts tests/testimonial-tags.test.ts tests/content-management.test.ts
npm run build
```

### 도구 모음 정리

글씨 크기는 기본·12·14·16·18·20·24·28·32·40·48 드롭다운으로 선택합니다. ± 버튼과 별도의 기본 색상 버튼은 제거합니다. 글자 색상은 A와 하단 막대에 현재 선택 색상을 표시하며, 기본 서식 복원은 ‘서식 지우기’를 사용합니다. 색상 선택 중에는 편집기 포커스를 강제로 이동하지 않고 저장한 선택 범위에 적용합니다.

정렬 아이콘 메뉴에는 왼쪽·가운데·오른쪽·양쪽 정렬을 표시합니다. 내어쓰기·들여쓰기는 번호 목록과 실행 취소 사이에 독립 아이콘으로 배치합니다. 줄 간격은 별도 기호 메뉴에서 선택합니다. 목록·들여쓰기·실행 취소 등의 기호는 동일한 SVG 스타일로 표시합니다. 개발 테스트 확인 전에는 PR을 새로 생성하거나 갱신하지 않습니다.

### 줄 및 단락 간격

줄 간격 메뉴는 한 줄·1.15·1.5·두 줄 프리셋과 단락 앞뒤 공백 추가/삭제, 맞춤 간격을 제공합니다. 맞춤 간격 창에서 줄 간격은 0.5~5배(소수점 두 자리), 단락 앞뒤 간격은 0~120px 정수로 입력합니다. 선택한 문단/제목에만 적용되며 취소하면 기존 값은 유지됩니다. ‘서식 지우기’는 간격과 페이지 옵션도 기본값으로 되돌립니다.

‘다음 문단과 함께 표시’, ‘줄 함께 표시’, ‘한 줄 누락 방지’, ‘앞에 페이지 나누기 추가’는 인쇄/PDF에서 적용됩니다. 웹 화면에는 강제로 빈 페이지를 만들지 않습니다. 완료 상태는 메뉴 체크 표시로 확인할 수 있습니다. 신규 속성도 기존 서식 JSON에 저장하므로 별도 DB 마이그레이션은 필요하지 않습니다.

## 멤버 소개의 참여한 기수

콘텐츠 관리의 소개 본문 다음에 ‘참여한 기수 (선택)’를 추가합니다. 기수마다 이름과 기간을 입력하고 추가·삭제할 수 있으며, 기간은 자유 형식으로 입력하거나 생략할 수 있습니다. 기간만 입력한 행에는 이름이 필요하고, 완전히 빈 행은 저장하지 않습니다.

공개 프로필에서는 소개와 관심 분야 사이에 기수명·기간 카드를 입력 순서대로 표시합니다. 참여 기수가 없으면 제목과 카드 영역 모두 표시하지 않습니다. 기존 계정의 ‘내 HANDA 히스토리’와 자동 연동하지 않고 관리자가 프로필별로 입력하는 공개 콘텐츠입니다. JSON의 선택 필드로 저장하므로 기존 프로필 호환성을 유지하고 별도 DB 마이그레이션은 필요하지 않습니다.

## 홈 배경 사진

콘텐츠 관리의 홈 편집에서 ‘홈 배경 사진’에 최대 10장을 등록하고 ‘한 장 고정’ 또는 ‘새로고침할 때마다 무작위 표시’를 선택합니다. 고정 모드에서는 사진 설명으로 원하는 사진을 고릅니다. 기존 콘텐츠와 빈 사진 목록은 `/brand/handa-main.jpg`를 사용하며, 정기모임 후기 카드의 기존 사진은 유지합니다. 무작위 모드는 요청 시 선택하므로 정적 캐시에서 하나로 고정되지 않으며, 같은 사진이 연속으로 선택될 수 있습니다.

사진 업로드는 기존 최적화·권한·저장소 절차를 사용합니다. 운영 배포 전에 `npm run db:migrate`로 `013_home_hero_photos.sql`을 적용해야 합니다. 이 마이그레이션은 기존 사진을 변경하지 않고 사진 테이블의 허용 콘텐츠 종류에 `home`을 추가합니다. 추가 환경변수는 필요하지 않습니다. 사진을 삭제·선택하거나 표시 방식을 변경한 뒤 저장해야 공개 홈에 반영됩니다.
