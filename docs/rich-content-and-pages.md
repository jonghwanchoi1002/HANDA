# 소개 페이지와 서식 편집

## 관리자 편집

**내 계정 → 콘텐츠 관리 → HANDA 소개**에서 HANDA란?, 운영 방식 및 참여 안내, 참여 신청하기를 수정합니다. 페이지 제목·본문 제목·본문·추가 안내와 참여 버튼 문구·URL을 관리할 수 있습니다. 소개 페이지 3개는 고정 주소를 사용하며 저장하면 바로 공개됩니다. 일반 멤버는 이 편집 화면과 저장 기능에 접근할 수 없습니다.

`011_editable_introduction_pages.sql`은 `page` 콘텐츠 종류와 고정 페이지 제약을 추가하고 세 페이지의 초기 내용을 넣습니다. HANDA란?에는 전달받은 소개 글과 강조 문장을 넣습니다. 본문 아래 **HANDA 참여 신청하기** 버튼은 `https://forms.gle/SXXxb8321efoPFta8`을 새 탭으로 엽니다. 이미 저장된 소개 페이지가 있으면 덮어쓰지 않습니다. 운영 방식과 다음 모집 알림 신청 절차는 추후 별도 결정합니다.

## 작성 도구

위키·멤버 소개·정기모임 후기·멤버 후기·홈 소개·소개 서브페이지의 제목과 본문에 공통 편집기를 제공합니다.

- 크기: 기본 / 12·14·16·18·20·24·28·32·40·48px
- 굵게, 기울임, 밑줄, 서식 지우기
- 기본 실행 취소·다시 실행 및 서식 단축키

분류·날짜·URL·관심 분야 같은 구조화된 입력과 사진 설명은 일반 입력을 유지합니다. 기존 글은 서식이 없는 상태로 그대로 읽고 수정할 수 있습니다. 멤버 위키의 소유권·공개 승인과 사진 접근 규칙도 유지합니다.

## 저장과 표시

일반 문자열과 문자열 배열은 검색·제목·메타데이터에 계속 사용합니다. 필드별 `richText` JSON, 위키 섹션의 `titleRichText`/`bodyRichText`, 후기 블록의 `richText`에 서식만 추가합니다. 서버는 문서 구조·허용 글씨 크기·마크를 검사하고 일반 텍스트와 서식 내용이 일치해야 저장합니다.

문단·줄바꿈·텍스트와 허용된 네 서식만 저장합니다. HTML 문자열을 실행하거나 `dangerouslySetInnerHTML`로 표시하지 않습니다. 임의 노드·속성·스타일은 서버에서 거절하며 화면은 React 요소로 렌더링합니다. 기존 리비전 검사와 감사 기록을 사용하므로 동시 수정이 다른 관리자의 내용을 덮어쓰지 않습니다.

## 개발 적용

```bash
npm ci
npm run db:migrate
npm run dev
```

마이그레이션이 소개 페이지를 추가하므로 별도 `db:seed`는 필요하지 않습니다. 운영 배포 전에 운영 DB에도 011을 적용해야 합니다. 새 서식은 기존 JSON에 선택 필드로 추가하므로 이전 글 전체를 변환할 필요가 없습니다.
