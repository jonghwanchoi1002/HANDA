# 내 계정과 일회성 이용 승인 안내

상단 메뉴 이름은 **멤버 소개**이며, **내 계정** 드롭다운과 페이지 이름은 그대로 유지합니다. 내가 쓴 글·콘텐츠 관리·회원 관리·로그아웃은 드롭다운에서 이용하고 개인정보 페이지에는 별도 바로가기 버튼을 두지 않습니다.

## 화면과 수정 범위

- 승인 대기 계정: 인사말·가입 이름·이메일과 **이용 승인 요청 대기 중** 안내 카드를 표시합니다.
- 승인된 일반 이메일 계정: 인사말, 프로필 사진 영역, 이름, 현재 이메일과 이메일 변경 요청, 비밀번호 변경을 표시합니다.
- Google 연결 계정: HANDA에서 사용하는 이름은 수정하고, 이메일은 읽기 전용으로 표시합니다. 이메일·비밀번호 변경 폼은 제공하지 않으며 해당 변경 API도 Google 연결 여부를 확인해 차단합니다.
- 이용 중지·거절 계정: 인사말·이름·이메일과 **이용 승인이 중지되었습니다** 안내 카드를 표시합니다. 위키 열람·글 작성 제한과 관리자 문의, 공개 페이지는 계속 열람할 수 있다는 점을 안내합니다.

프로필 사진은 기존 계정에 사진이 있으면 보여주고 없으면 이름의 첫 글자를 표시합니다. 사진 변경 버튼은 **준비 중** 상태입니다. 계정 프로필 사진 업로드는 이 변경에 포함하지 않습니다.

이름 변경은 HANDA에만 반영됩니다. 일반 이메일 계정은 변경 요청 시 기존 주소로 온 확인 링크를 누르고, 이어서 새 주소로 온 확인 링크도 눌러야 로그인 이메일이 바뀝니다. 모두 확인하기 전에는 기존 주소를 유지하며, 이메일을 바꾸어도 계정 ID·작성 글·이용 승인 상태는 유지됩니다. 기존 Resend 설정을 사용하므로 실제로 두 주소에 메일을 전달할 수 있어야 합니다.

비밀번호는 기존 값을 표시하거나 반환하지 않습니다. 현재 비밀번호를 확인하고 새 비밀번호 12~128자와 확인 값을 입력해 변경합니다. 변경 시 다른 기기의 세션은 폐기하고 현재 브라우저는 갱신된 세션으로 계속 이용합니다.

Google 계정 자체의 이메일·비밀번호는 HANDA에서 바꿀 수 없습니다. HANDA용 비밀번호는 Google 비밀번호와 별개이며, 과거 계정 복구에서 HANDA 비밀번호를 별도로 설정했을 수 있습니다. 이 화면에서는 Google 연결 계정이면 로컬 비밀번호 보유 여부와 무관하게 이메일·비밀번호 변경을 제한합니다. 기존의 비밀번호 재설정 링크는 HANDA 자격 증명을 다루는 별도의 복구 흐름이며 Google 비밀번호를 바꾸지 않습니다.

## 한 번만 나타나는 승인 완료 팝업

마이그레이션 `007_account_profile_notice.sql`이 사용자 테이블에 두 값을 추가합니다.

- `approval_notice_version`: 승인된 횟수에 따른 안내 버전
- `approval_notice_seen_version`: 해당 계정이 확인한 안내 버전

관리자 승인으로 상태가 승인됨으로 바뀌면 DB 트리거가 안내 버전을 증가시킵니다. 두 버전이 다를 때 로그인한 사용자에게 **이용 승인 완료** 팝업을 표시합니다. **확인**을 누르면 서버가 세션의 사용자 ID와 현재 승인 상태를 다시 확인하고, 표시한 버전이 현재 버전과 일치할 때 확인 버전을 저장합니다.

확인 기록은 쿠키나 로컬 저장소가 아니라 DB에 보관합니다. 따라서 새로고침·재로그인·다른 브라우저에서도 확인한 안내는 다시 나오지 않습니다. 확인 저장에 실패하면 팝업을 유지하고 다시 시도하도록 합니다. 오래된 탭의 확인 요청이 새 승인 안내까지 확인한 것으로 처리되지 않도록 버전 일치 조건을 사용합니다.

이용 중지 후 재승인된 경우에는 새 안내 버전이 생겨 한 번 더 표시됩니다. 같은 승인 상태에서 승인 버튼을 반복해서 누르거나 이름을 바꿔도 새 안내를 만들지 않습니다. 기존 승인 계정은 이 마이그레이션 적용 후 최초 한 번 안내를 받습니다.

안내는 `/account` 내 계정 페이지에서만 표시합니다. 다른 페이지와 내가 쓴 글 목록에서는 표시하지 않습니다. 내 계정 진입·창 포커스 시 현재 서버 기록을 확인하고, 화면이 보이는 동안 30초 간격으로 확인합니다. 브라우저에 남은 이전 페이지 데이터로 팝업을 먼저 열지 않으므로 확인한 안내가 화면 이동 후 다시 나타나지 않습니다. 확인 요청은 내비바 문구나 위치를 변경하지 않습니다. 승인 팝업의 확인 후 공통 데이터를 갱신하므로 대기 화면도 개인정보 화면으로 전환됩니다.

## 적용과 검증

```bash
npm run db:migrate
npm run dev
```

운영 배포 전에는 운영 DB를 대상으로 별도 적용합니다.

```bash
NODE_ENV=production npm run db:migrate
```

```bash
npm run test:profile
npm run test:auth
npm run test:access
```

테스트는 기존 승인 계정 마이그레이션, 승인·확인·중지·재승인, 오래된 확인 요청 거절, 이름 입력 검증과 보호 필드 조작 거절, 현재 비밀번호 확인과 다른 세션 폐기, 이메일 변경의 기존·새 주소 확인, Google 연결 계정의 변경 제한을 로컬 DB와 실제 인증 핸들러로 검증합니다. 브라우저 검증의 메일은 로컬 전송 모형으로 수집하며 실제 메일을 외부로 보내지 않습니다.

## 개인정보 공개 범위와 HANDA 히스토리

`008_profile_visibility.sql`은 계정별 `profile_visibility`를 추가합니다. 기본값은 기존·신규 계정 모두 `private`이며 `private`(비공개), `members`(멤버에게만), `public`(모든 방문객) 중 하나를 저장합니다. 현재 로그인한 승인 계정 본인의 설정만 수정할 수 있고, 유효하지 않은 값과 미승인·이용 중지 계정의 변경은 서버에서 거절합니다.

이번 단계는 설정 저장과 향후 조회 정책 준비까지입니다. 회원 프로필 공개 페이지나 관리자의 회원 상세 조회 기능을 새로 만들지 않으며, 현재 관리자가 작성한 멤버 소개 콘텐츠의 공개 여부를 이 설정으로 자동 변경하지 않습니다. 로그인 이메일·비밀번호는 이 공개 설정의 대상이 아닙니다.

`canViewMemberProfile`은 향후 공개 프로필 조회 시 재사용할 판별 함수입니다. 본인은 자신의 정보를 확인할 수 있고, 다른 사람이 보는 공개 프로필은 소유자도 이용 승인을 마친 상태여야 합니다. 비공개는 다른 사용자에게 숨기며 멤버 전용은 이메일 확인과 이용 승인을 마친 계정만, 전체 공개는 비로그인 방문객도 허용합니다. 이 공개 조회 정책에 관리자 예외를 자동으로 넣지 않았으며 향후 운영용 회원 상세 조회 권한은 별도로 정할 수 있습니다.

**내 HANDA 히스토리**의 가입일은 계정의 기존 `createdAt`에서 읽고 베를린 시간대로 표시합니다. 이름·공개 범위를 바꾸어도 가입일은 변경하지 않습니다. **참여한 기수**와 **참석한 모임**은 ‘추후 추가 예정’ 항목만 표시하며 임의의 횟수나 참여 기록을 만들지 않습니다. 모임 후기와 참석자의 연결 방식은 추후 정한 뒤 별도 구현합니다.
