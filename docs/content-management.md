# 관리자 콘텐츠 관리

관리자로 로그인하고 상단 **콘텐츠 관리** 메뉴를 엽니다 (`/admin/content`). 가입 회원 관리와 콘텐츠 관리는 별도 화면이며, 이메일 확인·이용 승인을 마친 관리자만 접근하고 저장할 수 있습니다. 일반 회원은 글을 작성하거나 수정할 수 없습니다.

## 설치와 DB 적용

새 환경 변수나 이미지 저장소 설정은 필요하지 않습니다. 기존 `DATABASE_URL`, 인증 환경 변수와 `CONTENT_SOURCE=database`를 사용합니다. 마이그레이션 004는 콘텐츠의 수정 버전과 변경 기록 테이블을 추가합니다. 기존 콘텐츠는 유지됩니다.

```bash
# 개발 DB: .env.local
npm run db:migrate
npm run dev
```

운영 배포 전에 `.env.production.local`이 production DB를 가리키는지 확인하고 아래 명령을 별도로 실행합니다. 개발 DB 변경은 운영 DB에 자동 복사되지 않습니다.

```bash
NODE_ENV=production npm run db:migrate
```

## 사용 방법

- **홈 소개:** 기존 홈 문구를 수정합니다. 저장하면 바로 반영되므로 공개 상태를 변경할 수 없습니다.
- **비즈니스 위키:** 제목, 분류, 요약, 섹션 제목과 본문을 입력합니다. 섹션을 추가·삭제하거나 순서를 변경할 수 있습니다. 공개해도 승인된 회원만 읽을 수 있습니다.
- **멤버 소개:** 이름, 사업 분야, 직함, 소개, 관심 분야와 선택 사항인 웹사이트를 입력합니다. 이 콘텐츠의 등록은 로그인 계정 생성이나 권한 부여와는 별개입니다.
- **모임 후기:** 제목, 요약, 날짜, 장소와 문단·소제목을 입력합니다. 문단을 추가·삭제하거나 순서를 변경할 수 있습니다.
- **참가자 이야기:** 이름, 소개, 이야기, 주제를 입력합니다. 실제 참가자 이야기를 공개하려면 공개 동의를 확인해야 합니다.

**새 글 작성**은 기본적으로 임시 저장 상태입니다. 필수 내용을 입력하고 저장한 뒤 필요할 때 **공개**로 바꿔 저장합니다. 공개한 글을 다시 임시 저장으로 바꾸면 방문자 목록과 상세 페이지에서 숨겨집니다. 임시 저장도 필수 항목은 모두 입력해야 합니다. 기존 링크가 유지되도록 글 주소는 생성 후 변경하지 않습니다.

표시 순서는 작은 숫자가 먼저입니다. 목록에서 제목·이름과 공개 상태로 검색할 수 있으며 페이지당 20개를 표시합니다. 실제 정보로 예시 글을 바꿀 때에는 **화면 예시용 콘텐츠입니다** 선택을 해제합니다.

사진 첨부는 다음 작업입니다. 이번 화면은 기존 사진과 이미지 정보를 유지하며, 새 사진 업로드 기능은 제공하지 않습니다.

## 저장과 변경 기록

서버는 매 저장 시 DB의 현재 관리자 권한을 확인하고 콘텐츠 형식을 검증합니다. 저장과 변경 기록은 하나의 트랜잭션으로 처리합니다. 기록에는 관리자 ID, 콘텐츠 종류·주소, 변경 전후 내용과 공개 상태가 포함됩니다. 변경 기록은 DB에 저장하며 이번 화면에서 복원 기능은 제공하지 않습니다.

동시에 같은 글을 수정하면 먼저 저장한 버전만 반영됩니다. 충돌 안내가 표시되면 입력한 내용을 복사해 둔 다음 새로고침해 최신 내용을 확인합니다. 저장 오류 시 입력 내용은 유지됩니다. 저장 성공은 화면의 안내 또는 새 글의 수정 화면으로 이동한 것으로 확인합니다.

## 검증

```bash
npm run test:content
npm run lint
npm run test:access
```

`test:content`는 로컬 테스트 DB에서 현재 권한 검증, 임시 저장·공개·공개 해제, 동시 수정 충돌, 변경 기록, 참가자 동의, 홈 공개 상태 보호와 기존 이미지 보존을 확인합니다. `test:access`는 실제 Next.js 서버에서 비회원·일반 회원의 관리자 화면 접근 차단과 비공개 위키 보호를 확인합니다.
