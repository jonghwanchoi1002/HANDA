# 공통 내비게이션 · 회원 위키 · 사진 첨부

## 이번 변경

모든 페이지가 최상위 레이아웃의 내비바 하나를 공유합니다. 데스크톱과 모바일에서 각각 일정한 높이로 화면 상단에 고정되며 페이지를 바꾸어도 다시 마운트하지 않습니다. 상단 메뉴는 로그인 상태와 무관하게 동일합니다. **내 계정** 드롭다운에서 계정 정보, 내가 쓴 글, 콘텐츠 관리, 회원 관리, 로그아웃으로 바로 이동합니다. 관리 링크는 관리자에게만, 내가 쓴 글은 승인된 회원에게만 표시하며 비로그인 사용자에게는 로그인·회원가입 링크를 제공합니다. 드롭다운이 열려도 내비바 높이와 위치는 바뀌지 않습니다. 관리 페이지와 저장 요청은 기존과 같이 서버에서 관리자 권한을 확인합니다.

내비바에서 세션 확인을 제거했으므로 계정 확인 중 문구가 나오지 않습니다. Next.js Link의 미리 불러오기와 공통 레이아웃으로 이동 중에도 메뉴가 유지됩니다. 페이지 본문의 DB·세션 확인과 이미지 전송 시간까지 없어지는 것은 아닙니다. 작은 화면에서는 메뉴 줄을 가로로 스크롤할 수 있습니다.

승인된 회원은 위키 검색창 옆 **새 글 작성**으로 위키를 작성하고, 내 계정의 **내가 쓴 글**(`/account/posts`)에서 임시 저장·공개 대기·공개 글을 관리합니다. 위키 목록에서는 내가 쓴 글 링크를 제거했습니다. 본인 글의 수정만 가능하며 관리자는 모든 글을 수정할 수 있습니다. 기존 예시·이전 글은 작성자가 지정되지 않았으므로 관리자만 수정할 수 있습니다. 다른 페이지의 콘텐츠는 관리자만 작성·수정합니다.

## 적용 순서

개발 DB와 운영 DB를 혼동하지 않도록 `.env.local`은 development, `.env.production.local`은 production 주소를 사용합니다. 새 기능에는 004·005·006 마이그레이션이 모두 필요합니다. 기존 회원·콘텐츠는 보존됩니다.

```bash
npm ci
npm run db:migrate
npm run dev
```

운영 배포 전 별도로 실행합니다.

```bash
NODE_ENV=production npm run db:migrate
```

`005_member_wiki_media.sql`은 콘텐츠 작성자와 업로드한 사진의 저장 위치를 기록합니다. `006_wiki_publication_review.sql`은 위키 전용 공개 대기 상태를 추가합니다. 회원 가입 상태나 관리자 권한은 변경하지 않습니다.

## Vercel Blob 연결

1. Vercel의 프로젝트 Storage에서 Blob 저장소를 만들고 **Private** 접근 방식을 선택합니다. Public 저장소를 사용하지 않습니다.
2. 테스트용 저장소는 Preview·Development에 연결하고 운영용 저장소는 Production에 별도로 연결하는 것을 권장합니다.
3. 연결하면 생성되는 `BLOB_READ_WRITE_TOKEN`을 해당 배포 환경 변수에 설정합니다. 토큰을 GitHub나 채팅에 올리지 않습니다. 프로젝트에 자동 추가됐다면 중복 등록할 필요가 없습니다.
4. PC에서 테스트할 때는 테스트 저장소의 토큰을 `.env.local`에 넣고 개발 서버를 재시작합니다.
5. Vercel 환경 변수 변경은 재배포 후 반영됩니다. `CONTENT_SOURCE=database`와 대상 DB 마이그레이션도 필요합니다.

```dotenv
BLOB_READ_WRITE_TOKEN=비공개_저장소의_토큰
```

키를 설정하기 전에도 글 작성·수정과 내비바는 사용할 수 있으며 사진 선택만 비활성화됩니다. 저장소 생성·토큰 설정과 실제 계정의 전송 확인은 프로젝트 소유자 환경에서 진행합니다.

## 사진 처리

사진 설명을 입력한 뒤 JPG·PNG·WebP 파일을 고릅니다. 한 장당 3MB, 한 글에 최대 10장입니다. 멤버 소개·참가자 이야기는 대표 사진 한 장, 모임 후기는 대표 사진과 본문 사진, 위키는 첨부 사진을 지원합니다. 위키 사진은 본문 아래에 표시됩니다. 모임 후기 본문 사진은 본문 편집에서 순서를 이동할 수 있습니다.

서버는 실제 파일을 해석하고, 최대 2400px로 크기를 조절한 WebP로 다시 저장합니다. 원본 위치 정보·메타데이터는 유지하지 않습니다. 단순 확장자 검사만으로 파일을 허용하지 않습니다. 사용자당 시간당 30회의 첨부 제한이 있습니다. 사진 첨부 후에는 글을 저장해야 공개 상태와 연결됩니다.

비공개 Blob의 URL이나 토큰을 방문자에게 직접 전달하지 않습니다. `/api/images/[id]`가 현재 접근 권한과 해당 글에 첨부된 사진인지 확인한 뒤 전달합니다. 공개된 멤버 소개·후기·동의한 참가자 이야기의 사진은 누구나 읽을 수 있지만 위키 사진은 승인된 회원만 읽을 수 있습니다. 임시 저장 사진은 작성자·관리자만 볼 수 있습니다. 모든 이미지 응답은 `private, no-store`를 사용합니다. 업로드 요청에는 같은 사이트 출처 확인과 현재 회원·작성자 권한 확인을 적용합니다.

글에서 사진을 제거하면 글에서는 숨겨지며 공개 접근도 차단됩니다. 업로드했지만 저장하지 않은 사진과 이전 수정 기록의 사진은 이 버전에서 자동 삭제하지 않습니다. 저장소 정리는 별도 운영 작업이며 즉시 삭제·복원 기능은 포함하지 않습니다.

## 검증

```bash
npm run lint
npm run test:content
npm run test:wiki
npm run test:access
```

- `test:wiki`: 회원의 위키 작성·본인 수정, 관리자 전용 범위, 권한 중지, 사진의 글 간 재사용 차단, 공개·임시 저장·회원 전용 접근, 이미지 형식·크기·첨부 횟수를 실제 로컬 DB와 이미지 디코더로 확인합니다.
- `test:access`: 실행 중인 Next 서버에서 비회원·미승인 회원·일반 회원의 보호 페이지 접근, 현재 DB 조회와 위키의 HTML/RSC 정보 보호를 확인합니다.
- 브라우저 검증: 메뉴의 실제 좌표와 DOM 유지, 로그인 후 내 계정 관리 링크, 멤버의 글 작성·수정·사진 첨부·공개, 비회원 사진 접근 차단, 일반 공개 프로필 사진을 확인했습니다. 이미지 전송은 공식 Blob SDK와 로컬 HTTP 저장소 모형으로 검증하며 실제 Vercel 계정의 Blob 연결은 별도 확인이 필요합니다.

Blob SDK의 간접 의존성 `@vercel/cli-config`가 고정한 구버전 Zod 대신 프로젝트의 같은 4.x 계열 Zod를 사용하도록 override를 두었습니다. 이미지 저장소 도입으로 알려진 고위험 운영 의존성 취약점이 추가되지 않도록 확인합니다.

## 관리자 공개 승인

위키 작성 상태는 **임시 저장 → 작성 완료 · 공개 대기 중 → 공개**입니다. 멤버에게는 임시 저장과 공개 대기만 제공하며, 서버도 멤버의 공개 요청을 거절합니다. 공개 대기 글과 사진은 작성자·관리자만 볼 수 있습니다. 관리자는 콘텐츠 관리의 **공개 대기** 필터에서 글을 확인하고 수정 화면에서 공개로 전환해 저장합니다.

기존에 공개된 글은 마이그레이션만으로 숨겨지지 않습니다. 다만 멤버가 공개 글을 수정해 저장하면 임시 저장 또는 공개 대기로 전환되어 비공개가 되며, 관리자의 재승인 후에 다시 공개됩니다. 관리자 수정은 직접 공개 상태를 유지할 수 있습니다.

작성 화면 아래에는 **저장 / 뒤로 / 내가 쓴 글 목록**이 있습니다. 뒤로를 누르면 저장하지 않은 내용이 사라진다는 대화상자가 나타나며 **취소**는 입력을 유지하고 **계속**은 저장하지 않고 위키 목록으로 이동합니다. 내가 쓴 글 목록을 누를 때도 저장하지 않은 변경이 있으면 확인합니다. 내 계정 페이지의 홈페이지로 버튼은 제거했습니다.

드롭다운은 공통 `NavDropdown` 컴포넌트로 작성해 다른 메뉴에도 사용할 수 있습니다. 클릭·키보드로 열 수 있고 Escape·바깥 클릭으로 닫으며, 작은 화면의 가로 내비바에 잘리지 않도록 별도 포털에 표시합니다.
